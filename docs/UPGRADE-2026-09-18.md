## Supabase / Vercel actions
1. In Supabase **Authentication → URL Configuration**, set the Site URL to:
   `https://commissioner.com.et`
2. Add these Redirect URLs:
   - `https://commissioner.com.et/`
   - `https://commissioner.com.et/reset-password`
   - Your Vercel production URL, if different.
   - Any Vercel preview URL you actually use for testing.
3. For email/password signup, keep email confirmation enabled if you want verified email accounts. Make sure Supabase email delivery/SMTP is configured for production.
4. If using Google sign-in, enable Google under **Authentication → Providers** and add the production redirect URL shown by Supabase.
5. In Vercel, keep these environment variables set for Production (and Preview if needed):
   - `VITE_SUPABASE_URL`
   - `VITE_SUPABASE_ANON_KEY`
6. Do **not** put a Supabase service-role key in Vercel client-side variables.
7. Apply only the Supabase SQL migrations that have not already been applied to the production project. Do not paste the entire collection repeatedly; several files are historical/fix migrations.
